# 无 Tag 物块视觉定位与机械臂抓取设计

日期：2026-07-16

## 1. 目标

在现有 Mirobot、Astra Pro、MoveIt 和吸泵链路上，增加对无 AprilTag 物资方块的抓取能力。

第一阶段只验证一块物资：操作者指定目标类别，程序先做 dry-run，确认像素、深度、相机坐标和 base 坐标合理后，再低速从方块正面吸取并撤回。放置位置和自动连续抓取四块不在第一阶段范围内。

目标物块的已知条件：

- 尺寸约为 100 mm x 100 mm。
- 白色方形外轮廓稳定，四条外边基本完整可见。
- 物块基本正对 Astra 相机。
- 支架颜色不固定，算法不能依赖蓝色背景。
- 抓取方向为正面水平吸取。

## 2. 已验证基础

模型目录：`/home/zcy/models/Block_yolov8n_640`

模型类别：

| 类别 ID | 模型类别 | 中文含义 |
| --- | --- | --- |
| 0 | Emergency power supply device | 应急电源 |
| 1 | Fire extinguishing device | 灭火装置 |
| 2 | Gas purification device | 气体净化装置 |
| 3 | Structural support device | 结构支撑 |

WSL 离线复测使用 9 张测试图片、36 个目标，结果为：

- Precision：0.937
- Recall：1.000
- mAP50：0.995
- mAP50-95：0.775

该结果证明模型可承担类别识别和候选区域检测，但测试集很小，且来自同一数据分布，不能替代比赛机现场图像验证。远距离目标中结构支撑类别的置信度相对最低，因此真机验证需要覆盖距离、光照和视角变化。

## 3. 总体架构

系统对操作者只暴露一个 Python 3 启动入口。内部保留 Python 2 ROS 进程，以兼容 ROS Melodic 的 `rospy`、`tf`、`moveit_commander` 和 `mirobotPump` 服务。

### 3.1 Python 3 主程序

职责：

- 解析目标类别、置信度阈值和 dry-run 等参数。
- 加载 YOLOv8 模型一次。
- 自动启动 Python 2 的 `mirobot_pick_test.py` 子进程。
- 对 Python 2 提供的 RGB 帧执行目标检测。
- 返回指定类别的检测框、类别和置信度。
- 管理子进程退出和错误传播，使操作者只需运行一条 Python 3 命令。

### 3.2 Python 2 抓取程序

复用 `/home/eaibot/handeye-calib/src/mirobot_pick_test.py`，新增无 Tag 抓取模式，不另写一套 MoveIt 动作实现。

职责：

- 订阅 Astra RGB、注册深度和相机内参。
- 将 RGB 帧交给 Python 3 检测器并获取目标 ROI。
- 在 ROI 附近拟合白色方块外轮廓，计算四边形中心。
- 从中心内缩区域读取有效深度中值。
- 使用相机内参把像素和深度反投影为相机三维坐标。
- 使用现有 TF 链把相机点转换为机械臂 `base` 坐标。
- 复用现有 MoveIt、正面接近、吸泵和撤回逻辑。

### 3.3 进程通信

采用本机 JSON 行协议，传输检测请求和结果，不传输 ROS 对象。图像通过临时文件或共享路径交接，避免在标准输入输出中传输大块二进制数据。

协议至少包含：

- 请求 ID 和图像路径。
- 目标类别。
- 检测框 `x1, y1, x2, y2`。
- 类别 ID、类别名称和置信度。
- 成功或失败状态及错误原因。

ROS 日志不得混入 JSON 通信通道；通信消息使用专用文件描述符或独立管道。

## 4. 视觉与三维定位

### 4.1 检测策略

YOLO 只负责判断类别和缩小搜索范围，不能直接把检测框中心作为最终吸取点。

处理流程：

1. 在 RGB 图像上检测指定类别。
2. 若同类有多个候选，第一阶段拒绝自动选择并报告歧义；后续自动抓取阶段再定义排序规则。
3. 适当扩展 YOLO ROI，保留物块完整外边。
4. 在 ROI 内做灰度、亮度和边缘处理。
5. 查找凸四边形轮廓，并按面积、长宽比、矩形度和边长筛选约 1:1 的白色方块。
6. 选择与 YOLO 框重合度和中心距离最合理的四边形。
7. 用四个角点的几何中心作为像素抓取中心。

算法不依赖支架颜色。找不到唯一可靠四边形时必须停止，不能退化为盲目使用 YOLO 框中心执行真机动作。dry-run 可显示候选轮廓，便于现场调阈值。

### 4.2 深度策略

必须使用已对齐到 RGB 的注册深度，例如 `/camera/depth_registered/image_raw`，不能把 RGB 像素直接用于未注册的 `/camera/depth/image_raw`。

在四边形中心附近取一个小型内缩区域：

- 排除 0、NaN、Inf 和超出合理工作距离的值。
- 使用有效深度中值，避免单像素空洞和噪声。
- 检查有效像素比例和深度离散程度。
- 深度不足或波动过大时停止动作。

RGB、注册深度和 CameraInfo 应使用时间近似同步。真机启动后必须核对图像尺寸、编码和 frame_id，不能假设 WSL 中的话题配置等于实际运行状态。

### 4.3 坐标转换

设物块中心像素为 `(u, v)`，注册深度为 `Z`，RGB 相机内参为 `fx, fy, cx, cy`：

```text
Xc = (u - cx) * Z / fx
Yc = (v - cy) * Z / fy
Pc = [Xc, Yc, Z]
```

然后构造位于实际相机光学帧下的 `PoseStamped`，通过现有 TF 转换到 `base`。禁止手工复制或硬编码手眼外参矩阵；以当前发布的 `camera_link`、`camera_rgb_optical_frame` 和 `base` TF 链为准。

## 5. 抓取动作

在 `mirobot_pick_test.py` 中增加 `block_grasp` 模式，并复用已有函数：

- `build_move_group`
- `go_wrist_forward`
- `execute_pose`
- `execute_cartesian_pose`
- `set_pump`

第一阶段动作顺序：

1. 获取一次稳定的目标三维位置。
2. 输出调试信息和 RViz 调试点。
3. dry-run 到此结束，不获取吸泵服务，不执行任何运动。
4. 真抓时先将吸盘调整为已验证的水平朝前姿态。
5. 保持当前已验证的末端正面姿态，不从单个深度点推断物块平面法向。
6. 使用实测的 `Link6 -> suction_tcp` 固定工具变换计算 Link6 接触位姿，不能直接沿相机光轴减去工具长度。
7. 将吸盘局部轴按同一末端姿态旋转到 `base`，并与相机正面观察方向做夹角硬校验；轴填错或姿态不一致时拒绝动作。
8. 沿验证后的吸盘轴生成预抓取点，默认间距约 0.03 m，并作为可调参数。
9. MoveIt 规划到预抓取点。
10. 沿吸盘轴执行笛卡尔直线靠近。
11. 开泵并等待吸附。
12. 沿原路径退回预抓取点。
13. 第一阶段保持吸泵开启并停在安全撤回点，等待人工后续处理。

目标点必须包含吸盘接触中心相对 `Link6` 的固定三维变换。工具长度和局部轴需要在真机以低速、小步长测定，不能把相机测得的物块表面点直接当作 `Link6` 原点目标，也不能未经验证就假设吸盘轴与相机光轴共线。

## 6. 参数与操作入口

Python 3 主入口至少支持：

- `--target`：`power`、`fire`、`gas`、`support`
- `--model`：模型路径，真机默认值指向 `/home/eaibot` 下同步后的模型
- `--confidence`：检测置信度阈值
- `--dry-run`：只定位和输出，不运动
- `--velocity-scale`、`--acceleration-scale`
- `--approach-gap`
- `--tool-offset`
- `--debug-image`：保存检测框、四边形、中心和深度采样区

第一阶段每次必须显式指定一个目标类别。自动依次抓四类属于后续阶段；届时应每抓走一块后重新识别剩余物块，不能一次计算四个坐标后连续使用旧坐标。

## 7. 失败保护

下列任一条件发生时，程序必须返回失败且不执行运动：

- 未识别到指定类别。
- 同一目标类别存在多个候选，无法唯一选择。
- 置信度低于阈值。
- 找不到唯一可靠的白色四边形。
- 四边形面积、长宽比或矩形度不符合要求。
- 注册深度无效、有效像素不足或波动过大。
- CameraInfo 与 RGB 分辨率不匹配。
- 相机帧到 `base` 的 TF 不存在或超时。
- 目标超出机械臂工作空间或低于安全高度。
- MoveIt 无法生成完整路径。
- 吸泵服务不可用或单片机没有有效回包。

真抓默认速度和加速度比例为 0.05 到 0.1。程序不得在定位失败时使用上一次成功坐标继续动作。

## 9. 验证顺序

### 9.1 WSL 离线验证

- 模型能加载，类别映射正确。
- 在训练集外的现场图片上检查检测结果。
- 用合成 RGB、深度和 CameraInfo 测试像素反投影。
- 测试轮廓中心不会退化为 YOLO 框中心。
- 测试所有失败条件都阻止运动请求。
- Python 2 脚本做语法级检查，Python 3 主入口做单元测试。

### 9.2 比赛机只读验证

- 确认 RGB、注册深度和 CameraInfo 话题存在且频率稳定。
- 确认注册深度与 RGB 在物块边缘处对齐。
- 确认 `camera_rgb_optical_frame` 到 `base` 的 TF 可用。
- dry-run 输出目标像素、深度、相机坐标、base 坐标和调试图。
- 在 RViz 中核对调试点确实落在方块正面中心。

### 9.3 比赛机最小动作验证

- 清空机械臂周围空间并准备急停。
- 单独验证吸盘水平朝前姿态。
- 速度和加速度从 0.05 开始。
- 先只到预抓取点，不接触物块。
- 再以小间距分步校准工具偏移。
- 最后执行一次正面吸取和原路撤回。
- 验证稳定后才提高到 0.1，并测试四个类别和不同位置。

## 10. 后续阶段

第一阶段通过后再实现：

- 每抓一块后重新识别并按固定顺序抓取全部四类。
- 四类物资分别对应可配置的放置坐标。
- 与主车比赛流程联动。
- 记录抓取成功状态，避免重复抓取。
- 现场数据不足时补采图片并重新评估模型，而不是仅降低置信度阈值。
