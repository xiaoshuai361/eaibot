# zcy_last 使用命令

## 1. 单独启动底盘

终端 1 只负责底盘驱动，保持运行：

```bash
source /opt/ros/melodic/setup.bash
source /home/eaibot/robocom_ws/devel/setup.bash
roslaunch xpkg_bringup bringup_basic_ctrl.launch
```

source /opt/ros/melodic/setup.bash
source /home/eaibot/robocom_ws/devel/setup.bash
python /home/eaibot/robocom_ws/src/slow_keyboard_teleop.py

`zcy_last.main` 不会启动或关闭底盘，只会检查 `/xnode_comm` 和 `/xnode_vehicle` 是否已经存在。

## 2. 进入任务环境

终端 2 执行：

```bash
source /opt/ros/melodic/setup.bash
source /home/eaibot/robocom_ws/devel/setup.bash
source /home/eaibot/mirobot_ws/devel/setup.bash
source /home/eaibot/handeye-calib/devel/setup.bash
conda activate ww
cd /home/eaibot/robocom_ws/src
```

正式比赛由 `zcy_last.main` 按抓取开关启动和关闭 Astra、MoveIt、手眼 TF、Tag 检测与抓取进程。除终端 1 的底盘外，不要提前手动启动这些节点。

## 3. 四种启动方式

不执行机械臂抓取，只运行九路口循迹、任务 YOLO 和红绿灯判断：

```bash
source /opt/ros/melodic/setup.bash
source /home/eaibot/robocom_ws/devel/setup.bash
source /home/eaibot/mirobot_ws/devel/setup.bash
source /home/eaibot/handeye-calib/devel/setup.bash
conda activate ww
cd /home/eaibot/robocom_ws/src
python3 -m zcy_last.main
```

仅在循迹开始前执行 B 点有 Tag 抓取，成功抓取 2 个目标；第一圈识别到对应区域后自动投递：

```bash
python3 -m zcy_last.main --tag-pick --tag-pick-count 2
```

临时只测试有 Tag 抓取、不执行第一圈投递：

```bash
python3 -m zcy_last.main \
  --tag-pick --tag-pick-count 2 \
  --no-tag-delivery
```

仅在第 3 个路口完成后执行 A 点无 Tag 抓取，成功抓取 3 个目标；楼宇识别后自动投递：

```bash
python3 -m zcy_last.main --untagged-pick --untagged-pick-count 3
```

临时只测试 A 点无 Tag 抓取、不执行楼宇投递：

```bash
python3 -m zcy_last.main \
  --untagged-pick --untagged-pick-count 3 \
  --no-untagged-delivery
```

B 点和 A 点都执行抓取：

```bash
python3 -m zcy_last.main \
  --tag-pick --tag-pick-count 2 \
  --untagged-pick --untagged-pick-count 3
```

`--tag-pick-count` 和 `--untagged-pick-count` 只能填写 `1..4`。数量表示必须成功抓取的目标数，不是固定类别顺序；程序按当前可见目标从左到右选择。

自动投递只使用实际成功入仓的 ID。B 点映射为：普通人群 `1`、医疗人群 `2`、可回收垃圾 `3`、其他垃圾 `4`。A 点映射为：电力故障楼宇 `1`、火灾楼宇 `2`、有毒气体楼宇 `3`、坍塌楼宇 `4`。投递时底盘保持停止，成功后继续循迹；失败只输出警告并继续，不自动重试该 ID。

四个独立开关为 `--tag-pick/--no-tag-pick`、`--tag-delivery/--no-tag-delivery`、`--untagged-pick/--no-untagged-pick`、`--untagged-delivery/--no-untagged-delivery`。投递依赖对应抓取产生库存；关闭抓取时，即使打开投递开关也不会执行。

正式比赛前必须存在两套投递示教文件：

```text
/home/eaibot/handeye-calib/config/delivery_presets.json
/home/eaibot/handeye-calib/config/untagged_delivery_presets.json
```

## 4. 临时关闭抓取

即使 `config.py` 中默认打开了抓取，也可以通过命令临时关闭：

```bash
source /opt/ros/melodic/setup.bash
source /home/eaibot/robocom_ws/devel/setup.bash
source /home/eaibot/mirobot_ws/devel/setup.bash
source /home/eaibot/handeye-calib/devel/setup.bash
conda activate ww
cd /home/eaibot/robocom_ws/src
python3 -m zcy_last.main --no-tag-pick --no-untagged-pick
```

命令行开关优先于 `config.py` 顶部的默认开关。

## 5. 使用人工启动的 ROS 依赖

仅在调试且全部 ROS 依赖已经人工启动时使用：

```bash
python3 -m zcy_last.main --external-ros
```

`--external-ros` 模式不会启动、检查或关闭外部 ROS 进程，不建议用于正式比赛。

## 6. 失败处理

发生目标不足、Tag TF 超时、抓取失败、共享摄像头占用或依赖进程退出时，任务进入 `PICK_FAILED` 并永久停车。投递失败不会进入 `PICK_FAILED`，会在终端报警后继续循迹。日志位置：

```text
/home/eaibot/logs/zcy_last/<启动时间>/
```

修复故障后重新启动整套任务。完整状态机和摄像头切换说明见同目录 `README.md`。
