# zcy_last 使用命令

以下命令在机器人 `/home/eaibot` 上运行。Windows 开发路径不能直接用于机器人。

## 1. 终端一：launch 启动常驻依赖

```bash
source /opt/ros/melodic/setup.bash
source /home/eaibot/robocom_ws/devel/setup.bash
source /home/eaibot/mirobot_ws/devel/setup.bash
source /home/eaibot/handeye-calib/devel/setup.bash
conda activate ww
cd /home/eaibot/robocom_ws/src
python3 -m zcy_last.launch
```

source /opt/ros/melodic/setup.bash
source /home/eaibot/robocom_ws/devel/setup.bash
python /home/eaibot/robocom_ws/src/slow_keyboard_teleop.py

`launch.py` 只负责启动或复用底盘，临时启动 Astra，再启动 MoveIt 和手眼 TF。确认就绪后会关闭临时 Astra；若某个相机 nodelet 未随 roslaunch 退出，会逐节点限时关闭并清理 ROS Master 中已经失效的注册。最终只让底盘、MoveIt 和手眼 TF 常驻。它不会自动运行比赛任务。

看到以下提示后，保持终端一运行：

```text
[zcy_last] 基础依赖已就绪：底盘、MoveIt 和手眼 TF 常驻，临时 Astra 已关闭
```

## 2. 终端二：按需手动启动 main 任务

先进入任务环境：

```bash
source /opt/ros/melodic/setup.bash
source /home/eaibot/robocom_ws/devel/setup.bash
source /home/eaibot/mirobot_ws/devel/setup.bash
source /home/eaibot/handeye-calib/devel/setup.bash
conda activate ww
cd /home/eaibot/robocom_ws/src
```

然后从第 3 节五种组合中选择一条 `main.py` 命令运行。

`main.py` 启动后会：

```text
直接使用终端一已经启动好的底盘、MoveIt 和手眼 TF，不重复等待检查
-> 按任务阶段启停 Astra、Tag 检测和任务 YOLO
-> 按开关执行抓取、投递和九路口任务
-> 正常结束、异常或 Ctrl+C 时停车
-> 只关闭终端二自己启动的任务进程
```

是否运行 `main.py` 由用户决定。任务结束后，可继续保留终端一的常驻依赖；不再需要时，在终端一按 `Ctrl+C` 自动清理。

## 3. 五种比赛组合

以下命令都在终端一 `python3 -m zcy_last.launch` 显示基础依赖已就绪后，于终端二运行。

```bash

```


### 3. A 点无 Tag：抓取 4 个并投递

```bash
python3 -m zcy_last.main \
  --no-tag-pick \
  --untagged-pick --untagged-pick-count 4 --untagged-delivery
```

### 4. A/B 都抓取 4 个并投递

```bash
source /opt/ros/melodic/setup.bash
source /home/eaibot/robocom_ws/devel/setup.bash
source /home/eaibot/mirobot_ws/devel/setup.bash

  --untagged-pick --untagged-pick-count 4 --untagged-delivery
```

### 5. A/B 都抓取 4 个，都不投递

```bash
python3 -m zcy_last.main \
  --tag-pick --tag-pick-count 4 --no-tag-delivery \
  --untagged-pick --untagged-pick-count 4 --no-untagged-delivery
```

抓取数量只能是 `1..4`。命令行开关优先于 `config.py` 默认值。

临时联调时如果只想测试单个点“抓取但不投递”，可在对应的第 2 或第 3 种
命令中把该点的 `--*-delivery` 改成 `--no-*-delivery`；这两种调试写法不计入
正式五种比赛组合。

## 4. main 任务入口说明

`main` 不启动底盘，也不重复检查终端一的底盘、MoveIt、机械臂服务和手眼 TF；运行前应先确认终端一已经显示“基础依赖已就绪”。开启抓取时，它直接使用终端一的常驻依赖，并只按任务阶段管理 Astra、Tag 栈和抓取子进程。Astra 启动后只等待一次有效 RGB 内参；Tag 栈启动后只等待一次补白图像对应的 CameraInfo，避免后续节点在输入尚未建立时直接运行。

终端二从 `python3 -m zcy_last.main` 启动时开始使用单调时钟计时，运行中不刷计时信息。整条路线进入 `DONE` 并完成退出清理后打印一次“全部任务完成，总耗时：X分XX秒”；在完成前按 `Ctrl+C` 则在清理后打印一次“任务已中断，已运行：X分XX秒”。

`--external-ros` 会关闭依赖托管和检查，只用于全部依赖都由人工管理的特殊调试，不用于正式比赛。

`main` 启动前还会检查 `task/competition.py` 与 `control/grasp.py` 的运行接口。
无 Tag 命令必须包含 `--allow-partial` 且不能包含 `--fail-on-skip`；若检测到文件混用
旧版本，会在启动相机和底盘运动前直接退出。出现版本不一致提示时必须完整同步
`/home/eaibot/robocom_ws/src/zcy_last/`，不能只替换 `main.py`。开启无 Tag 抓取时还会
检查 `/home/eaibot/handeye-calib/src/block_pick_main.py` 和
`mirobot_pick_test.py`：父脚本必须支持部分成功，机械臂子脚本必须支持实际到位判定和
关节稳定后重试；任何一个仍是旧版都会在运动前退出。

### 从第 3 个右转后已摆正的位置调试 A 点

先把车放在正常流程完成第 3 个右转、出口横条摆正后的位置和朝向。终端一保持
`python3 -m zcy_last.launch` 运行，终端二执行：

```bash

source /home/eaibot/robocom_ws/devel/setup.bash
source /home/eaibot/mirobot_ws/devel/setup.bash
source /home/eaibot/handeye-calib/devel/setup.bash

cd /home/eaibot/robocom_ws/src
cd /home/eaibot/robocom_ws/src

  --start-untagged-aligned \
  --untagged-pick-count 4 \
  --untagged-delivery
```

该入口自动关闭 B 点抓取并开启 A 点抓取，不要再同时传 `--tag-pick` 或
`--no-untagged-pick`。程序从 `A_PICK_PREPARE` 开始：先停车加载 Astra、模型和
识别窗口；全部就绪后按正常 A 点时序直行搜索、抓取，抓取后等待绿灯并执行第 4 个
路口的专用左转，随后继续剩余路线和楼宇投递。命令启动后底盘会真实运动，放车位置和
朝向必须正确。

只测试 A 点抓取、不测试后续投递时，将最后一个参数改为
`--no-untagged-delivery`。

## 5. 当前任务时序

固定路线：

```text
右、直、右、左、直、左、右、直、右
```

- B 点有 Tag 抓取在循迹开始前执行。
- B 点抓取后先判断绿灯，再按独立时间执行第一次直行和右转。
- A 点无 Tag 抓取在第 3 个路口完成后触发；底盘停车等待 Astra、模型、抓取子进程和识别窗口全部就绪，先以 `FOLLOW_SPEED`、零角速度直行 2 秒，再降为独立低速边走边搜索，不使用巡线修正。
- A 点抓取后先判断绿灯，再按独立时间直行和完成第 4 个路口左转。
- B 点目标缺失、对准失败、Tag TF 超时或限位未接触时跳过该 ID，按实际库存继续。
- A/B 两点都按单个目标容错：某个目标未出现、对准/TF/限位或机械臂动作失败时跳过该目标，继续尝试其余目标，最后按实际成功库存继续比赛。只有父进程、结果文件或托管依赖等整批故障才进入 `PICK_FAILED`。投递失败只报警并继续。
- 楼宇识别使用独立的 `YOLO_BUILDING_STABLE_FRAMES=2`，同一楼宇类别连续确认 2 帧后才触发停车；需要继续延后时只调整这个参数。

## 6. 现场参数

配置文件：

```text
/home/eaibot/robocom_ws/src/zcy_last/config.py
```

常用参数：

```python
PICK_DEBUG_VIEW = True
DEBUG_VIEW = True

YOLO_PEOPLE_STABLE_FRAMES = 7
YOLO_TRASH_STABLE_FRAMES = 2

TAG_PICK_FIRST_ENTRY_TIME = 5.5
TAG_PICK_FIRST_TURN_TIME = 4.0
TAG_PICK_TF_WAIT_SECONDS = 18.0

A_PICK_THIRD_RIGHT_ENTRY_TIME = 6.5
A_PICK_THIRD_RIGHT_TURN_TIME = 4.0
UNTAGGED_SEARCH_STABLE_FRAMES = 3
UNTAGGED_SEARCH_FORWARD_TIME = 6.0
UNTAGGED_SEARCH_SPEED = 0.03
UNTAGGED_PICK_NEXT_ENTRY_TIME = 5.5
UNTAGGED_PICK_NEXT_TURN_TIME = 4.0

TURN_ENTRY_TIME = 6.5
TURN_TIME = 4.0
TURN_SPEED = 0.16
TURN_ANGULAR = 0.58

STOP_STABLE_FRAMES = 1
EXIT_ENTRY_IGNORE_TIME = 3.0
```

- 第一次右转起转太早：增加 `TAG_PICK_FIRST_ENTRY_TIME`。
- 第一次右转不足：增加 `TAG_PICK_FIRST_TURN_TIME`。
- 底盘对准后 Tag TF 更新较慢：调整 `TAG_PICK_TF_WAIT_SECONDS`。
- A 点前第 3 个右拐的前进距离：调整 `A_PICK_THIRD_RIGHT_ENTRY_TIME`；车在 A 点一侧停得太近时优先小幅增加。
- A 点前第 3 个右拐的转向角度：调整 `A_PICK_THIRD_RIGHT_TURN_TIME`；右转不足就增加，转过头就减小。
- A 点模型就绪后的快速直行时间：调整 `UNTAGGED_SEARCH_FORWARD_TIME`。
- A 点快速直行后边走边搜索的速度：调整 `UNTAGGED_SEARCH_SPEED`；角速度固定为零。
- A 点抓取后左转起转太早：增加 `UNTAGGED_PICK_NEXT_ENTRY_TIME`。
- A 点抓取后左转不足：增加 `UNTAGGED_PICK_NEXT_TURN_TIME`。
- 普通转弯起转时机：调整 `TURN_ENTRY_TIME`。
- 普通转弯角度：调整 `TURN_TIME` 或 `TURN_ANGULAR`。
- 入口横条当前单帧确认：`STOP_STABLE_FRAMES = 1`。
- 每次出口完成后 `3.0` 秒内忽略新入口横条，避免出口被重新识别成入口：`EXIT_ENTRY_IGNORE_TIME = 3.0`。
- A 点发现阶段使用全画面确认要求数量的不同物资；误触发时优先增加 `UNTAGGED_SEARCH_STABLE_FRAMES`，不要把发现区缩成抓取对齐区。

## 7. 窗口和日志

`PICK_DEBUG_VIEW = True` 时，B 点只显示一个 `tag_pick_detection` 合成窗口，其中包含 AprilTag 检测底图、YOLO ID 框、黄色中心点和红色底盘对准 ROI。A 点显示无 Tag 检测窗口。`DEBUG_VIEW = True` 时显示巡线、任务 YOLO 和红绿灯窗口。

A 点进入逐个抓取后，窗口继续画出所有剩余物资，但底盘每次只选择其中一个计算慢速对齐命令；成功后剩余框数量依次从4变为3、2、1。命令仍使用 `--max-targets 4` 尽力抓满4个，`--allow-partial` 只负责避免单个失败导致整车永久停车。

B 点有 Tag 连续抓取已直接删除每个目标抓取前的启动回零逻辑，不使用跳过参数。A 点无 Tag 抓取保持原逻辑：每个目标启动回零后等待关节状态稳定，再执行第一段 `block_approach_staging`。若 MoveIt 轨迹控制器报告执行失败，程序会读取实际末端误差：已在位置15mm、姿态0.35rad容差内则接受；否则等待关节稳定、刷新当前起点并重试一次。仍失败时日志会打印最终位置毫米误差和姿态角度误差，然后跳过该目标继续比赛。

B 点检测窗口只在选择目标和底盘对准期间显示。进入单个 ID 的机械臂长动作前会主动关闭，避免 MoveIt 阻塞期间因 OpenCV 不再处理窗口事件而被 Ubuntu 判为“无响应”；该 ID 完成后，下一目标开始对准时窗口会自动重开。这不会停止 YOLO、TF 或抓取流程。

日志目录：

```text
/home/eaibot/logs/zcy_last/<启动时间>/
```

两个终端会各自创建一个启动时间目录。终端一目录优先查看 `base.log`、`moveit.log` 和 `handeye_tf.log`；终端二目录优先查看 `astra.log`、`tag_relay.log`、`apriltag.log` 和 `pick_*.log`。

B 点抓取时终端只实时显示精炼状态：可处理 Tag 数量与从左到右顺序、当前 ID、红框停车、TF 等待/跳过、单次成功和最终实际库存。失败时会明确打印新 TF 超时、TF 稳定样本不足、TF 过期/链路未连通、限位未接触，或机械臂子进程退出码及末尾真实错误。A 点 `Block mono RGB - q/Esc to close` 窗口在模型 ready 前先显示一帧，之后即使没有检测框也持续刷新原始 RGB 和搜索 ROI。完整 ROS、MoveIt 与机械臂输出仍保存在 `pick_tag.log`。

## 8. 无 Tag 楼宇投递首次标定与示教

先备份真机上的 `delivery_presets.json`、`untagged_delivery_presets.json` 和全部抓取 preset。Windows 仓库不包含、也不能覆盖这些真机数据。

四类楼宇一起做真实距离标定。范围为 `350~600mm`，在机械臂 P 的示教参考距离
`450mm` 附近的 `400~500mm` 每 `10mm` 加密，每类每个距离采集5帧。脚本按
距离优先：同一距离依次采集四类，再调整下一个距离；一条命令共采集280帧：

标定只需要下面这一个终端，不要启动底盘、MoveIt、RViz、Astra、手眼 TF 或
`zcy_last.main`。先关闭其他楼宇预览程序，并用 `fuser /dev/video2` 确认没有进程
占用摄像头；无输出即为空闲。

```bash
source /opt/ros/melodic/setup.bash
source /home/eaibot/robocom_ws/devel/setup.bash
conda activate ww
cd /home/eaibot/robocom_ws/src

python3 -m zcy_last.building_delivery_calibrate \
  --distances 350,400,410,420,430,440,450,460,470,480,490,500,550,600 \
  --frames 5 --reference-distance-mm 450
```

程序会在每个距离依次用中文提示电力故障、火灾、有毒气体、坍塌四类楼宇；四类
完成后再改变距离。启动后检测窗口会立即显示；在终端或检测窗口按 Enter 自动记录当前
组合的5帧。只要框的左右边界完整即可，上下裁切不影响；中断后重新运行会跳过已有 CSV。
标定窗口的红色竖框为原始320×240画面的 `x=54~173`；检测框中心进入红框才会
采样，正式循迹停车也使用并显示同一个红框。
四类模型都拟合成功后一次性原子更新：

```text
/home/eaibot/handeye-calib/config/building_delivery_calibration.json
```

楼宇距离标定完成后，把车辆正对楼面停在 `450mm` 参考距离。先启动 Astra、
MoveIt/RViz 和手眼 TF（命令与无 Tag 抓取相同）。先示教无 Tag 楼宇投递专用
中转点：

```bash
source /opt/ros/melodic/setup.bash
source /home/eaibot/mirobot_ws/devel/setup.bash
source /home/eaibot/handeye-calib/devel/setup.bash
cd /home/eaibot/handeye-calib/src

python2 /home/eaibot/handeye-calib/src/mirobot_delivery.py \
  --mode teach_transit \
  --delivery-file /home/eaibot/handeye-calib/config/untagged_delivery_presets.json \
  --overwrite
```

再使用电力故障楼宇 ID1 手动示教一次四类共享的预投递点 P：

```bash
python2 /home/eaibot/handeye-calib/src/mirobot_delivery.py \
  --mode teach_contact_release \
  --sequence 1 \
  --delivery-file /home/eaibot/handeye-calib/config/untagged_delivery_presets.json \
  --overwrite
```

程序不会自动移动机械臂。直接在 RViz 中把吸盘移动到靠近、正对但不接触楼面的
P，再回终端按 Enter；程序保存当前六关节角，并由手眼 TF 保存相机前后方向。
正式投递 ID1～4 都读取这个 ID1 共享 P，但四类楼宇仍使用各自的框宽距离模型。

正式 `main.py --untagged-delivery` 会自动使用固定流程：楼宇框中心进入红框 `x=54~173` 即停车 -> 框宽估距，根据“实测距离减450mm”沿前后方向修正 P，送给机械臂前饱和限制在 `-5mm~+60mm` -> 仓内取物 -> 楼宇专用中转点 -> 修正后 P 的后方 30mm -> 开限位 -> 5mm 步长到 P -> 2mm 步长最多前探 65mm -> 关泵等待 0.7 秒 -> 直退 30mm -> idle。P 的高度和姿态保持示教值；底盘不做旋转或距离二次调整。走满 65mm 未触发会醒目报警但仍强制释放并记为成功；限位服务、串口或轨迹执行异常则保持泵开启并按投递失败处理。
