# zcy_last 使用命令

以下命令在机器人 `/home/eaibot` 上运行。Windows 开发路径不能直接用于机器人。

## 1. 终端一：launch 启动常驻依赖

```bash
source /opt/ros/melodic/setup.bash
source /home/eaibot/robocom_ws/devel/setup.bash
source /home/eaibot/mirobot_ws/devel/setup.bash
source /home/eaibot/handeye-calib/devel/setup.bash
conda activate ww
cd /home/eaibot/robocom_ws/src
python3 -m zcy_last.launch
```

source /opt/ros/melodic/setup.bash
source /home/eaibot/robocom_ws/devel/setup.bash
python /home/eaibot/robocom_ws/src/slow_keyboard_teleop.py

`launch.py` 只负责启动或复用底盘，临时启动 Astra，再启动 MoveIt 和手眼 TF。确认就绪后会关闭临时 Astra，只让底盘、MoveIt 和手眼 TF 常驻。它不会自动运行比赛任务。

看到以下提示后，保持终端一运行：

```text
[zcy_last] 基础依赖已就绪：底盘、MoveIt 和手眼 TF 常驻，临时 Astra 已关闭
```

## 2. 终端二：按需手动启动 main 任务

先进入任务环境：

```bash
source /opt/ros/melodic/setup.bash
source /home/eaibot/robocom_ws/devel/setup.bash
source /home/eaibot/mirobot_ws/devel/setup.bash
source /home/eaibot/handeye-calib/devel/setup.bash
conda activate ww
cd /home/eaibot/robocom_ws/src
```

然后从第 3 节五种组合中选择一条 `main.py` 命令运行。

`main.py` 启动后会：

```text
直接使用终端一已经启动好的底盘、MoveIt 和手眼 TF，不重复等待检查
-> 按任务阶段启停 Astra、Tag 检测和任务 YOLO
-> 按开关执行抓取、投递和九路口任务
-> 正常结束、异常或 Ctrl+C 时停车
-> 只关闭终端二自己启动的任务进程
```

是否运行 `main.py` 由用户决定。任务结束后，可继续保留终端一的常驻依赖；不再需要时，在终端一按 `Ctrl+C` 自动清理。

## 3. 五种比赛组合

以下命令都在终端一 `python3 -m zcy_last.launch` 显示基础依赖已就绪后，于终端二运行。

### 1. 只循迹，A/B 都不抓取

```bash
python3 -m zcy_last.main \
  --no-tag-pick \
  --no-untagged-pick
```

### 2. B 点有 Tag：抓取 4 个并投递

```bash
source /opt/ros/melodic/setup.bash
source /home/eaibot/robocom_ws/devel/setup.bash
source /home/eaibot/mirobot_ws/devel/setup.bash
source /home/eaibot/handeye-calib/devel/setup.bash
conda activate ww
cd /home/eaibot/robocom_ws/src
python3 -m zcy_last.main \
  --tag-pick --tag-pick-count 4 --tag-delivery \
  --no-untagged-pick
```

### 3. B 点有 Tag：只抓取 4 个，不投递

```bash
python3 -m zcy_last.main \
  --tag-pick --tag-pick-count 4 --no-tag-delivery \
  --no-untagged-pick
```

### 4. A 点无 Tag：抓取 3 个并投递

```bash
python3 -m zcy_last.main \
  --no-tag-pick \
  --untagged-pick --untagged-pick-count 3 --untagged-delivery
```

### 5. A 点无 Tag：只抓取 3 个，不投递

```bash
python3 -m zcy_last.main \
  --no-tag-pick \
  --untagged-pick --untagged-pick-count 3 --no-untagged-delivery
```

抓取数量只能是 `1..4`。命令行开关优先于 `config.py` 默认值。

## 4. main 任务入口说明

`main` 不启动底盘，也不重复检查终端一的底盘、MoveIt、机械臂服务和手眼 TF；运行前应先确认终端一已经显示“基础依赖已就绪”。开启抓取时，它直接使用终端一的常驻依赖，并只按任务阶段管理 Astra、Tag 栈和抓取子进程。Astra 启动后只等待一次有效 RGB 内参；Tag 栈启动后只等待一次补白图像对应的 CameraInfo，避免后续节点在输入尚未建立时直接运行。

`--external-ros` 会关闭依赖托管和检查，只用于全部依赖都由人工管理的特殊调试，不用于正式比赛。

## 5. 当前任务时序

固定路线：

```text
右、直、右、左、直、左、右、直、右
```

- B 点有 Tag 抓取在循迹开始前执行。
- B 点抓取后先判断绿灯，再按独立时间执行第一次直行和右转。
- A 点无 Tag 抓取在第 3 个路口完成后触发；模型就绪后固定直行搜索，不使用巡线修正。
- A 点抓取后先判断绿灯，再按独立时间直行和完成第 4 个路口左转。
- 投递失败只输出警告并继续；抓取失败进入 `PICK_FAILED` 停车。

## 6. 现场参数

配置文件：

```text
/home/eaibot/robocom_ws/src/zcy_last/config.py
```

常用参数：

```python
PICK_DEBUG_VIEW = True
DEBUG_VIEW = True

TAG_PICK_FIRST_ENTRY_TIME = 5.5
TAG_PICK_FIRST_TURN_TIME = 4.0

UNTAGGED_SEARCH_ROI = (0.60, 0.05, 0.98, 0.95)
UNTAGGED_SEARCH_STABLE_FRAMES = 3
UNTAGGED_SEARCH_FORWARD_SPEED = 0.16
UNTAGGED_PICK_NEXT_ENTRY_TIME = 5.5
UNTAGGED_PICK_NEXT_TURN_TIME = 4.0

TURN_ENTRY_TIME = 6.5
TURN_TIME = 4.0
TURN_SPEED = 0.16
TURN_ANGULAR = 0.58
```

- 第一次右转起转太早：增加 `TAG_PICK_FIRST_ENTRY_TIME`。
- 第一次右转不足：增加 `TAG_PICK_FIRST_TURN_TIME`。
- A 点搜索直行速度：调整 `UNTAGGED_SEARCH_FORWARD_SPEED`，方向固定不修正。
- A 点抓取后左转起转太早：增加 `UNTAGGED_PICK_NEXT_ENTRY_TIME`。
- A 点抓取后左转不足：增加 `UNTAGGED_PICK_NEXT_TURN_TIME`。
- 普通转弯起转时机：调整 `TURN_ENTRY_TIME`。
- 普通转弯角度：调整 `TURN_TIME` 或 `TURN_ANGULAR`。
- A 点右侧物块误触发：缩小 `UNTAGGED_SEARCH_ROI` 或增加稳定帧数。

## 7. 窗口和日志

`PICK_DEBUG_VIEW = True` 时，B 点只显示一个 `tag_pick_detection` 合成窗口，其中包含 AprilTag 检测底图、YOLO ID 框、黄色中心点和红色底盘对准 ROI。A 点显示无 Tag 检测窗口。`DEBUG_VIEW = True` 时显示巡线、任务 YOLO 和红绿灯窗口。

日志目录：

```text
/home/eaibot/logs/zcy_last/<启动时间>/
```

两个终端会各自创建一个启动时间目录。终端一目录优先查看 `base.log`、`moveit.log` 和 `handeye_tf.log`；终端二目录优先查看 `astra.log`、`tag_relay.log`、`apriltag.log` 和 `pick_*.log`。

## 8. 无 Tag 楼宇投递首次标定与示教

先备份真机上的 `delivery_presets.json`、`untagged_delivery_presets.json` 和全部抓取 preset。Windows 仓库不包含、也不能覆盖这些真机数据。

四类楼宇一起做真实距离标定。范围为 `350~600mm`，在机械臂 P 的示教参考距离
`450mm` 附近的 `400~500mm` 每 `10mm` 加密，每类每个距离采集5帧。脚本按
距离优先：同一距离依次采集四类，再调整下一个距离；一条命令共采集280帧：

标定只需要下面这一个终端，不要启动底盘、MoveIt、RViz、Astra、手眼 TF 或
`zcy_last.main`。先关闭其他楼宇预览程序，并用 `fuser /dev/video2` 确认没有进程
占用摄像头；无输出即为空闲。

```bash
source /opt/ros/melodic/setup.bash
source /home/eaibot/robocom_ws/devel/setup.bash
conda activate ww
cd /home/eaibot/robocom_ws/src

python3 -m zcy_last.building_delivery_calibrate \
  --distances 350,400,410,420,430,440,450,460,470,480,490,500,550,600 \
  --frames 5 --reference-distance-mm 450
```

程序会在每个距离依次用中文提示电力故障、火灾、有毒气体、坍塌四类楼宇；四类
完成后再改变距离。启动后检测窗口会立即显示；在终端或检测窗口按 Enter 自动记录当前
组合的5帧。只要框的左右边界完整即可，上下裁切不影响；中断后重新运行会跳过已有 CSV。
标定窗口的红色竖框为原始320×240画面的 `x=54~173`；检测框中心进入红框才会
采样，正式循迹停车也使用并显示同一个红框。
四类模型都拟合成功后一次性原子更新：

```text
/home/eaibot/handeye-calib/config/building_delivery_calibration.json
```

楼宇距离标定完成后，把车辆正对楼面停在 `450mm` 参考距离。先启动 Astra、
MoveIt/RViz 和手眼 TF（命令与无 Tag 抓取相同），然后使用电力故障楼宇 ID1
手动示教一次四类共享的预投递点 P：

```bash
source /opt/ros/melodic/setup.bash
source /home/eaibot/mirobot_ws/devel/setup.bash
source /home/eaibot/handeye-calib/devel/setup.bash
cd /home/eaibot/handeye-calib/src

python2 /home/eaibot/handeye-calib/src/mirobot_delivery.py \
  --mode teach_contact_release \
  --sequence 1 \
  --delivery-file /home/eaibot/handeye-calib/config/untagged_delivery_presets.json \
  --overwrite
```

程序不会自动移动机械臂。直接在 RViz 中把吸盘移动到靠近、正对但不接触楼面的
P，再回终端按 Enter；程序保存当前六关节角，并由手眼 TF 保存相机前后方向。
正式投递 ID1～4 都读取这个 ID1 共享 P，但四类楼宇仍使用各自的框宽距离模型。

正式 `main.py --untagged-delivery` 会自动使用固定流程：楼宇框中心进入红框 `x=54~173` 即停车 -> 框宽估距，根据“实测距离减450mm”沿前后方向修正 P -> 仓内取物 -> 修正后 P 的后方 30mm -> 开限位 -> 5mm 步长到 P -> 2mm 步长最多前探 65mm -> 关泵等待 0.7 秒 -> 直退 30mm -> idle。P 的高度和姿态保持示教值；底盘不做旋转或距离二次调整。走满 65mm 未触发会醒目报警但仍强制释放并记为成功；限位服务、串口或轨迹执行异常则保持泵开启并按投递失败处理。
