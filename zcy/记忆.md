- 2026-05-23 更新：机械臂启动默认不再依赖 /dev/KATA 或 /dev/ttyUSB0、/dev/ttyUSB1，而是改用系统自带稳定路径。
- 机械臂默认串口：/dev/serial/by-path/pci-0000:00:14.0-usb-0:6.1:1.0-port0。
- 吸泵单片机默认串口：/dev/serial/by-path/pci-0000:00:14.0-usb-0:6.2:1.0-port0。
- 只要 USB 线还插在现在这两个物理口位上，串口名漂移不会再影响启动；如果换了口位或换了 USB 集线器口位，默认路径要一起改。

## 7. 当前已经确认过的关键结论

这些是已经验证过的工程事实，后续 AI 不要重复走弯路：

1. easy_handeye 在当前 eye-on-base 模式下，OpenCV 后端方向本身没有根本性错误。
2. publish.py 过去的硬编码 180 度翻转是错误修法，当前不应恢复。
3. kata_astra_calibration.launch 和 publish.launch 的发布链路应以 camera_link 为统一 tracking base frame。
4. “xyz 挤成一点”不仅可能是算法问题，也可能是界面显示方向和自动采样策略问题；当前这两处都已做过修正。
5. 终端 3 不应再默认起第二个 RViz，否则会和终端 2 的 MoveIt RViz 混淆。
6. 终端 3 看到 world 相关 TF 报黄，通常是 RViz Fixed Frame 设错，不一定是 TF 真断。
7. rqt_virtual_joy/plugin.xml not found 一般不是当前标定失败的根因，可暂时忽略。

## 9. 标定与抓取的验收标准

### 9.1 手眼标定是否靠谱

```bash
source /opt/ros/melodic/setup.bash

rosrun tf tf_echo Link6 camera_marker
```

然后让机械臂去 5 到 8 个没有专门采样过的新姿态：

- 好的标定：Link6 -> camera_marker 只小范围抖动
- 差的标定：位置或姿态随机械臂姿态大幅漂移

### 9.2 抓取是否靠谱

- dry-run 能找到标签且 MoveIt 不报错
- 真抓时能接近、吸附、抬起、撤回
- 不再出现 TF for tag_x was not found

## 10. 常见坑与优先排查顺序

### 10.1 package not found / mesh not found

优先检查当前终端是否少了：

```bash
source /home/eaibot/mirobot_ws/devel/setup.bash
```

### 10.2 TF 全黄，提示 No transform to world

优先检查 RViz 的 Fixed Frame 是否错误设成了 world，应改为 base。

### 10.3 标定结果方向离谱

优先检查：

1. 是否错误发布到 camera_rgb_optical_frame 而不是 camera_link
2. publish.py 是否被重新引入了硬编码翻转
3. ArUco 的 marker_size 是否填错
4. ArUco 是否在标定后被重新挪动过

### 10.4 xyz 样本看起来都挤到一起

优先检查：

1. rqt_easy_handeye.py 的显示方向逻辑
2. handeye_robot.py 的自动位姿生成逻辑
3. 用户是否只在中心附近采样、没有充分改变姿态

### 10.5 抓取偏差固定朝一个方向

优先调：

1. --z-offset
2. --y-offset
3. --grasp-x

每次只改一个量，步长建议 0.001 到 0.003 米。
