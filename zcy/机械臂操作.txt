机械臂操作说明

一、最常用命令
1. 机械臂回零
python2 /home/eaibot/handeye-calib/src/mirobot_pick_test.py --mode home

2. 单独测试吸泵
python2 /home/eaibot/handeye-calib/src/mirobot_pick_test.py --mode pump

3. 按标签抓取
python2 /home/eaibot/handeye-calib/src/mirobot_pick_test.py --mode grasp --tag-id 1

4. 按物资类型抓取
python2 /home/eaibot/handeye-calib/src/mirobot_pick_test.py --mode grasp --supply basic
python2 /home/eaibot/handeye-calib/src/mirobot_pick_test.py --mode grasp --supply medical
python2 /home/eaibot/handeye-calib/src/mirobot_pick_test.py --mode grasp --supply recyclable
python2 /home/eaibot/handeye-calib/src/mirobot_pick_test.py --mode grasp --supply hazardous

5. 从抓取点正上方下压抓取
python2 /home/eaibot/handeye-calib/src/mirobot_pick_test.py --mode grasp --supply basic --approach-axis z --approach-gap 0.02 --velocity-scale 0.1 --acceleration-scale 0.1

5.0.1 单独把吸盘转成水平朝前姿态
python2 /home/eaibot/handeye-calib/src/mirobot_pick_test.py --mode wrist_forward --velocity-scale 0.05 --acceleration-scale 0.05 --planning-time 8.0

5.1 面朝 AprilTag 正面抓取
先用 dry run 看姿态和位置：
python2 /home/eaibot/handeye-calib/src/mirobot_pick_test.py --mode grasp --supply basic --skip-home --dry-run --planning-time 2.0 --disable-replanning --velocity-scale 0.1 --acceleration-scale 0.1 --grasp-x 0.08 --y-offset 0.025 --z-offset -0.08 --approach-axis front --approach-gap 0.03 --front-tool-pitch-deg 90 --debug-hold-seconds 30

确认姿态合理后再执行真机：
python2 /home/eaibot/handeye-calib/src/mirobot_pick_test.py --mode grasp --supply basic --skip-home --planning-time 8.0 --velocity-scale 0.1 --acceleration-scale 0.1 --grasp-x 0.08 --y-offset 0.025 --z-offset -0.08 --approach-axis front --approach-gap 0.03 --front-tool-pitch-deg 90

6. 抓起后放到任意 base 坐标点
python2 /home/eaibot/handeye-calib/src/mirobot_pick_test.py --mode pick_place --supply basic --approach-axis z --approach-gap 0.02 --place-x 0.180 --place-y 0.000 --place-z 0.080 --place-approach-gap 0.02 --velocity-scale 0.1 --acceleration-scale 0.1

7. 已经吸住物体后，单独放到任意点
python2 /home/eaibot/handeye-calib/src/mirobot_pick_test.py --mode place --place-x 0.180 --place-y 0.000 --place-z 0.080 --place-approach-gap 0.02 --velocity-scale 0.1 --acceleration-scale 0.1

8. 读取当前末端坐标，直接生成放置参数
python2 /home/eaibot/handeye-calib/src/mirobot_pick_test.py --mode current_pose

9. 演示用：抓起后抬高 5cm，再原地下放并关泵
python2 /home/eaibot/handeye-calib/src/mirobot_pick_test.py --mode pick_lift_place --supply basic --skip-home --planning-time 2.0 --disable-replanning --grasp-x -0.024 --y-offset 0.026 --z-offset 0.076 --approach-axis z --approach-gap 0.02 --lift-height 0.1 --velocity-scale 0.1 --acceleration-scale 0.1

10. 建议先用慢速
--velocity-scale 0.1 --acceleration-scale 0.1
二、脚本说明
1. mirobot_pick_test.py 统一负责 home、pump、grasp、place、pick_place、pick_lift_place、current_pose、wrist_forward 和内部 block_grasp 九种模式；无 Tag 模式的操作员入口仍是 Python 3 主脚本。
2. --mode home 不会开吸泵。
3. --mode pump 只测吸泵。
4. --mode grasp 会先识别 AprilTag，再移动机械臂，再开吸泵抓取。
5. --mode place 会把当前已经吸住的物体移动到指定 base 坐标，再关闭吸泵释放。
6. --mode pick_place 会先抓取，再自动移动到指定 base 坐标放下。
7. --mode pick_lift_place 会先抓取，再向上抬高指定高度，然后回到原抓取点下放并关闭吸泵。
7. --mode current_pose 会读取当前末端在 base 坐标系下的位置，并打印可直接复制的 --place-x / --place-y / --place-z。
7. --mode wrist_forward 会只把 joint5 转到已验证的吸盘水平朝前姿态，不开吸泵。
7. 当 --approach-axis z 时，脚本会先到抓取点正上方，再做竖直下压和竖直抬起。
5. 如果机械臂已经在 home，执行 --mode home 可能看起来没有动作，这是正常的。
5. 当前吸泵底层已经改成独立单片机串口控制，不再使用机械臂原本的 M3 吸泵指令。
6. switch_pump_status 服务现在会向系统自带的稳定串口路径 /dev/serial/by-path/pci-0000:00:14.0-usb-0:6.2:1.0-port0 发送字符 1 开泵、字符 2 关泵；串口参数是 115200、8N1、无流控。
7. 单片机收到命令后只要有任意串口回包，底层就判定这次吸泵命令成功；没有回包则会返回失败。
三、常用参数
1. --mode：home / pump / grasp / place / pick_place / pick_lift_place / current_pose / wrist_forward / block_grasp（block_grasp 只由 Python 3 主脚本内部调用）
2. --tag-id：直接抓指定 AprilTag，例如 --tag-id 1
3. --supply：basic / medical / recyclable / hazardous
4. --velocity-scale、--acceleration-scale：速度和加速度比例
5. --grasp-x：前后补偿
5.1 默认 pre_grasp 不再固定用 -0.07，而是自动取 grasp-x - approach-gap
5.2 当 --approach-axis z 时，grasp-x 仍然控制最终抓取点的前后补偿，但 pre_grasp 会切换成“抓取点正上方”。
5.3 当前 basic 在没有手动传 --grasp-x / --y-offset / --z-offset 时，会自动套用已验证可执行的一组预设：0.0 / 0.0 / 0.09。
6. --y-offset：左右补偿
7. --z-offset：高低补偿
8. --dry-run：只算位姿，不执行真机动作
9. --planning-time：单次规划最多等多久
10. --disable-replanning：调参时失败更快，不反复重试
11. --skip-home：连续调参时不先回 home
12. --debug-hold-seconds：dry run 后把目标点保留几秒，方便在 RViz 看
13. --approach-axis：x 或 z。x 表示前后接近，z 表示先到上方再向下抓。
13.1 新增 front：表示先到 AprilTag 正面前方的 pre_grasp，再沿标签正面法线向前接近 grasp。此时 grasp-x 表示相对标签面的正面距离，y-offset 表示沿标签左右偏移，z-offset 表示沿标签上下偏移，末端姿态会跟随标签再叠加 front-tool 角度补偿。
14. --approach-gap：pre_grasp 和 grasp 的间距。x 模式下是前后距离，z 模式下是上方高度。
14.1 front 模式下，approach-gap 表示 pre_grasp 比 grasp 离标签面再远多少。
15. --place-x、--place-y、--place-z：放置点在 base 坐标系下的绝对坐标。
16. --place-approach-gap：放置时先停在目标点上方多高，再竖直下放，默认 0.02 米。
17. --skip-post-grasp-retreat：抓住后不先回到 pre_grasp，机械臂停在抓取点；只建议单独 grasp 调试时使用。
18. --lift-height：pick_lift_place 模式下，抓住后先向上抬高多少米，再原地下放释放；默认 0.05 米。
19. --front-tool-roll-deg、--front-tool-pitch-deg、--front-tool-yaw-deg：仅 front 模式使用。用于把末端吸盘从当前默认朝向旋到正对标签；如果 --front-tool-pitch-deg 90 方向反了，就试 -90。
20. --wrist-forward：抓取前先把 joint5 转到吸盘水平朝前姿态。当前验证值是 joint5=-1.5709534265016345。
21. --wrist-forward-joint5：覆盖 --wrist-forward 使用的 joint5 目标弧度，默认 -1.5709534265016345。

第 3 步：确认机械臂基础动作
终端 1：
source /opt/ros/melodic/setup.bash
source /home/eaibot/mirobot_ws/devel/setup.bash
roslaunch mirobot_moveit_config mirobot.launch start_rviz:=false

注释：上面这条启动命令现在默认同时使用两个串口。
1. 机械臂本体默认走系统自带稳定路径 /dev/serial/by-path/pci-0000:00:14.0-usb-0:6.1:1.0-port0。
2. 吸泵单片机默认走系统自带稳定路径 /dev/serial/by-path/pci-0000:00:14.0-usb-0:6.2:1.0-port0。
3. 只要两根线还插在现在这两个 USB 口上，就不会再受 /dev/ttyUSB0、/dev/ttyUSB1 漂移影响。
4. 如果你把线换到别的 USB 口，或者换了 USB 集线器口位，这两个稳定路径会变，launch 默认值也要跟着改。

如果怀疑当前线缆口位变了，或者日志里出现下面这些提示：
1. Didn't receive robot state (joint angles) with recent timestamp within 1 seconds.
2. Failed to fetch current robot state.
3. Failed to validate trajectory: couldn't receive full current joint state within 1s
可直接显式指定机械臂串口，例如：
source /opt/ros/melodic/setup.bash
source /home/eaibot/mirobot_ws/devel/setup.bash
roslaunch mirobot_moveit_config mirobot.launch serial_port:=/dev/serial/by-path/pci-0000:00:14.0-usb-0:6.1:1.0-port0
如果机器卡、不想打开 RViz，就加 start_rviz:=false：
roslaunch mirobot_moveit_config mirobot.launch start_rviz:=false serial_port:=/dev/serial/by-path/pci-0000:00:14.0-usb-0:6.1:1.0-port0

如果吸泵单片机的串口号变化了，可显式指定：
source /opt/ros/melodic/setup.bash
source /home/eaibot/mirobot_ws/devel/setup.bash
roslaunch mirobot_moveit_config mirobot.launch serial_port:=/dev/serial/by-path/pci-0000:00:14.0-usb-0:6.1:1.0-port0 pump_serial_port:=/dev/serial/by-path/pci-0000:00:14.0-usb-0:6.2:1.0-port0
如果机器卡、不想打开 RViz，就加 start_rviz:=false：
roslaunch mirobot_moveit_config mirobot.launch start_rviz:=false serial_port:=/dev/serial/by-path/pci-0000:00:14.0-usb-0:6.1:1.0-port0 pump_serial_port:=/dev/serial/by-path/pci-0000:00:14.0-usb-0:6.2:1.0-port0

如果不想启动时先执行固件回零，而是直接去 0 关节位姿，可改用：
source /opt/ros/melodic/setup.bash
source /home/eaibot/mirobot_ws/devel/setup.bash
roslaunch mirobot_moveit_config mirobot.launch start_rviz:=false auto_home_on_start:=false move_to_zero_pose_on_start:=true

终端 2：
source /opt/ros/melodic/setup.bash
source /home/eaibot/mirobot_ws/devel/setup.bash
python2 /home/eaibot/handeye-calib/src/mirobot_pick_test.py --mode home
python2 /home/eaibot/handeye-calib/src/mirobot_pick_test.py --mode pump

注释：--mode pump 现在的底层行为是：
1. 调用 ROS 服务 switch_pump_status。
2. 服务向稳定路径 /dev/serial/by-path/pci-0000:00:14.0-usb-0:6.2:1.0-port0 发送字符 1，等待单片机回包。
3. 到时间后再发送字符 2，等待单片机回包。

判断标准：
1. home 能成功回零。
2. pump 能开关吸泵。

补充说明：
1. 默认 roslaunch mirobot_moveit_config mirobot.launch 仍会先执行固件回零，这个更稳。
2. auto_home_on_start:=false move_to_zero_pose_on_start:=true 会跳过固件回零，直接下发 0 关节位姿。
3. 这个“直接到初始点”模式只建议在同一通电周期内使用，也就是机械臂当前位置没有因为断电或手动挪动而失真。
4. 如果刚重新上电、断电后重启、或者你手动掰过机械臂，还是建议先正常回零一次。

标定顺序：
1. 先在终端 2 的 MoveIt RViz 里把机械臂摆到合适起始姿态。
2. 再用终端 3 的 Local Mover 点 Check starting pose / Next Pose / Plan / Execute。
3. 每到一个新姿态，在 Hand-eye Calibration 里点一次 Take Sample。
4. 至少采样 18 次后点 Compute。
5. 结果正常后点 Save。

补充：
1. Local Mover 失败不代表标定做不了，只代表当前起始姿态不适合自动采样。
2. 可以完全不用 Local Mover，直接在终端 2 的 MoveIt RViz 里手动移动一次、采一次。
3. Save 后建议关闭终端 3，再进入发布阶段。

注意：
1. marker_size 必须改成你末端 ArUco 黑码真实边长。
2. 位置和角度都要变化，不要只在中间采。
3. 不要同时在终端 2 和终端 3 两边一起发运动命令。
4. 当前 kata_astra_calibration.launch 已关闭 dummy_handeye 假 TF。
5. RViz 若提示 No transform to world，先把 Fixed Frame 改成 base。

第 6 步：确认 AprilTag 检测正常
当前 AprilTag 检测配置：
1. tag_family 使用 tag16h5。
2. 只允许比赛用真实 ID 1、2、3、4，误识别出来的 15、26、12、18 等 ID 不允许映射成有效目标。
3. 如果终端提示 Requested description of standalone tag ID [15]/[26]/[12]/[18]，说明当前图像把小码误识别了，需要改善图像质量、分辨率、距离、光照或重新打印更清晰的 tag16h5 1-4。
4. max_hamming_dist 当前使用 1，优先减少误识别。近距离画面糊时可能漏检，但比把错误 ID 当成有效目标更安全。
5. continuous_detection.launch 默认会打开 /tag_detections_image 预览窗口，方便看检测框。
6. 当前 astrapro.launch 默认 RGB 图像是 640x480，AprilTag 识别吃的是 /camera/rgb/image_raw。
7. 如果换了打印尺寸，必须同步修改 /home/eaibot/mirobot_ws/src/apriltag_ros/apriltag_ros/config/tags.yaml。
8. 如果看到 /tag_detections_image 窗口，那是 image_view 预览，不是 RViz。

近距离识别不稳定时：
1. 优先把 tag 放到相机更清晰的距离识别，不要强行贴近相机。
2. 识别稳定后，机械臂抓不到属于抓取偏移、手眼标定或可达范围问题，再调 grasp-x / y-offset / z-offset。
3. 如果 max_hamming_dist 改成 2 后误识别明显变多，比赛时不建议用 2。

8.4 registered depth 是硬门槛
无 Tag 抓取不能使用未对齐的 /camera/depth/image_raw 代替。执行前先检查：
rostopic hz /camera/rgb/image_raw
rostopic hz /camera/depth_registered/image_raw
rostopic echo -n 1 /camera/rgb/camera_info
rostopic echo -n 1 /camera/rgb/image_raw/header
rostopic echo -n 1 /camera/depth_registered/image_raw/header

必须确认：
1. /camera/depth_registered/image_raw 真实存在且持续出数据。
2. registered depth 已对齐到 RGB，图像尺寸、光学坐标系和时间戳可与 RGB 对应。
3. /camera/rgb/camera_info 的内参与当前 RGB 分辨率一致。
4. 还必须用真机图像可视化工具查看 RGB 与 registered depth 的边缘叠加效果：物块、框架和背景的深度跳变边缘必须与 RGB 边缘重合。只有尺寸相同不能证明已完成配准；边缘叠加不对齐就是硬阻断。
5. 任一项不满足就停止，不进入真机抓取。程序也会再次校验 RGB/depth 尺寸、frame、时间差、编码和深度有效性，校验失败时不发送动作。
