## 预期效果

运行后会打开巡线摄像头 `VideoCapture(2)`，发布 `/cmd_vel` 控车。

默认会弹出一个处理图窗口：

```text
line_cy_processed
```

这个窗口不是原始摄像头图，而是二值化后的算法图，叠加了：

```text
绿色矩形：巡线 ROI 区域
灰色竖线：图像中心
蓝色：识别到的黑线分组
青色：实际左/右参考线
紫色：补出来的虚拟线
绿色点：巡线中心点
红色框：停止横线
黄色框：斑马线条纹
顶部文字：状态、follow_mode、停车置信度、lane_width、丢线次数
```

正常双线时，小车应沿两条黑线中间巡迹。

接近路口时，只有检测到“停止横线在斑马线靠车一侧”并连续稳定出现，才停车。停车后按 `turn_cmd` 通过：

```text

left：优先跟左线，补右线左转
right：优先跟右线，补左线右转
```

````bash
### 斑马线接近、摆正和通过

当前斑马线入口动作分为四个状态：

```text
FOLLOW_LINE：正常巡线
APPROACH_CROSSWALK：屏蔽斑马线横条/竖条，沿真实边线低速靠近
ALIGN_STOPLINE：横条到画面底部后停车，根据横条角度原地摆正
CROSSWALK_WAIT：入口丢失或摆正超时，持续停车等待人工检查
MANEUVER：横条水平稳定后，按 turn_cmd 通过斑马线
```

通过斑马线时，`straight` 使用普通巡线，不再进入“跟右线、补左线”的模式；`left/right` 在刚离开停车横条的 `enter_intersection_straight_time` 时间内也先普通巡线，之后才按指定方向补线。

进入 `MANEUVER` 后，脚本会保留一小段斑马线屏蔽记忆。即使后半段只能看到 1-2 根残留竖条，仍会继续把它们从巡线图中清掉，防止突然被当成边线。

处理图中：

```text
红色旋转框：停车横条
黄色旋转框：斑马线竖条，这些区域已经从巡线图中清除
橙色横线：开始停车摆正的画面高度
angle：停车横条相对水平线的角度
bottom：停车横条最下方位置占画面高度的比例
align：已连续水平的帧数/要求帧数
```

当前斑马线条纹不会再按“只要细长就算”来识别。脚本会要求条纹同时满足“比较粗、比较短、至少 3 根、横向成组、尺寸和角度相近”。单独的道路边线、被切碎的边线片段、太细太长的斜线不会进入黄色条纹框，也不会从巡线图里被清掉。

如果只先识别到左边线，右边线暂时丢失，脚本会先检查边线是否在多条扫描行里前后连续。斑马线竖条这种短块如果没有形成连续边线，会被忽略或被斑马线屏蔽，不应该再把它当右边边线。

停车横条也会和成组条纹做空间关系检查。只有横条确实位于斑马线靠车一侧，且在条纹组中心位置处的投影关系合理，才会触发 `APPROACH_CROSSWALK`。如果看到左侧边线被画成红框，优先检查是否已经同步最新 `line_cy.py`。

先在真机只检查识别，不控制底盘：

```bash
python3 line_cy.py _dry_run:=true _detect_only:=true _debug_view:=true _raw_view:=true
```

要检查 `APPROACH_CROSSWALK -> ALIGN_STOPLINE -> MANEUVER` 状态切换，但仍然不向底盘发布速度：

```bash
python3 line_cy.py _turn_cmd:=straight _dry_run:=true _detect_only:=false _debug_view:=true _raw_view:=true
```

这里必须保持 `_dry_run:=true`。`_detect_only:=false` 只是允许状态机继续运行，便于观察调试文字。

`_detect_only:=true` 时不会发布任何底盘速度；只有 `_dry_run:=false _detect_only:=false` 同时满足时才会控制小车。

确认红色横条角度和黄色条纹框稳定后，再低速启用：

```bash
python3 line_cy.py _turn_cmd:=straight _dry_run:=false _detect_only:=false _line_speed:=0.10 _approach_crosswalk_speed:=0.06 _align_max_angular:=0.25
```

如果横条越调越斜，立即停车并把旋转方向取反：

```bash
python3 line_cy.py _turn_cmd:=straight _dry_run:=false _detect_only:=false _line_speed:=0.10 _approach_crosswalk_speed:=0.06 _align_max_angular:=0.25 _align_angular_sign:=-1.0
```

常用斑马线参数：

```text
approach_crosswalk_speed   默认 0.06，靠近停车横条的速度
align_trigger_y_ratio      默认 0.82，横条下边缘到这里后开始摆正
align_angle_tolerance_deg  默认 3.0，允许的水平角度误差
align_stable_frames        默认 5，连续水平多少帧后才通过
align_timeout              默认 5.0，对齐超时后停车等待，不盲目通过
align_angular_sign         默认 1.0，旋转方向相反时改为 -1.0
crosswalk_lost_frames      默认 6，允许检测短暂丢失的帧数
crosswalk_track_confidence 默认 0.52，接近阶段红框还在但置信度下降时继续跟踪，不立刻判丢
```

### Ctrl-C 后终端不恢复的原因和处理

如果看到类似：

```text
rospy.exceptions.ROSInitException: Failed to initialize time
```

通常是 ROS master/底盘 bringup 没有启动，或者当前终端没有正确 source ROS 环境。先确认已经执行：

```bash
source /opt/ros/melodic/setup.bash
source /home/eaibot/robocom_ws/devel/setup.bash
roslaunch xpkg_bringup bringup_basic_ctrl.launch
```

如果程序已经打印：

```text
line_cy 已启动: camera_index=2
```

但按 `Ctrl-C` 之后迟迟不回到命令行，主要原因是 OpenCV 的 `VideoCapture.read()` 或窗口显示可能卡在 C/C++ 层，Python 的中断信号不能马上打断它。

当前 `line_cy.py` 已改成后台线程读取摄像头，主线程只取最新帧，正常按一次 `Ctrl-C` 应该能进入清理流程并释放摄像头。

如果现场仍然卡住，可以按顺序处理：


### 1. 先确认画面

先不要追求速度，确认 `line_cy_processed` 里黑线能被稳定二值化，ROI 框能覆盖车前方有效循迹区域。

如果黑线断裂多、噪声多，先别调 PID，优先看光照、摄像头角度、阈值。

### 2. 调正常巡线

常用参数：

```text
line_speed           默认 0.10
roi_top_ratio        默认 0.28，绿色 ROI 上边界
roi_bottom_ratio     默认 0.68，绿色 ROI 下边界；当前已比之前加大一点
kp_small / kd_small  小偏差 PID
kp_big / kd_big      大偏差 PID
max_angular          最大角速度
```

现象与处理：

```text
左右抖动明显：降低 kp_big、kp_small 或 max_angular
普通弯道拐不过来：先把 line_speed 降到 0.12~0.16，再增大 max_angular 到 1.2~1.5
普通弯道仍拐不过来：增大 kp_big，例如 0.022 -> 0.030 -> 0.040
弯道回正太猛或抖动：降低 kp_big，或略增 kd_big
直线太慢：小幅增加 line_speed
容易冲出线：降低 line_speed
```

推荐先试这个保守弯道命令：

```bash
python3 line_cy.py _dry_run:=false _detect_only:=false _line_speed:=0.14 _max_angular:=1.35 _kp_big:=0.035
```

### 3. 调停车识别

常用参数：

```text
stop_stable_frames   默认 3
stop_confidence_min  默认 0.68，首次识别到斑马线入口的最低置信度
stop_hold_time       默认 1.0
stop_cooldown_time   默认 5.0
```

现象与处理：

```text
该停不停：先看红色停止线和黄色斑马线框有没有画出来；可把 stop_stable_frames 从 3 降到 2
误停车：把 stop_stable_frames 增大到 4 或 5
同一路口反复停：增大 stop_cooldown_time
```

注意：不要为了“更容易停”把顺序判断去掉，必须保持停止横线在斑马线靠车一侧才触发。

### 4. 调补线和路口通过

常用参数：

```text
side_follow_speed        默认 0.10
lane_width_pixels        默认 0，>0 时强制使用这个像素宽度补线
default_lane_width_ratio 默认 0.56
roi_top_ratio            默认 0.24
roi_bottom_ratio         默认 0.76
left_turn_bias           默认 0.12
right_turn_bias          默认 0.12
straight_bias            默认 0.0
recover_dual_frames      默认 10
intersection_min_time    默认 1.2
intersection_max_time    默认 15.0
```

现象与处理：

```text
左转不够：增大 left_turn_bias，或降低 side_follow_speed
左转过头：减小 left_turn_bias
右转不够：增大 right_turn_bias，或降低 side_follow_speed
右转过头：减小 right_turn_bias
直行偏左/偏右：微调 straight_bias；现在 straight 不再强制右线补左线
补线中心明显不对：先看处理图顶部 width=xxx，稳定后用 _lane_width_pixels:=xxx 固定
自动估计刚开始不准：调 default_lane_width_ratio，或直接指定 _lane_width_pixels
太早退出路口：增大 recover_dual_frames
路口迟迟不退出：减小 recover_dual_frames，或检查双线是否真的重新出现
绿色 ROI 框偏小：现场可继续加大 _roi_bottom_ratio，或减小 _roi_top_ratio
```

单边补线时，同一条连续边线不会因为跨过图像中心线就从左线翻成右线。处理图里如果看到一条连续左边线跨过灰色中心线，紫色虚拟线仍应补在它右侧；反之右边线应补在左侧。

双边线识别时，每一行最多只保留两条 active 边线；两条边线中间的斑马线块、噪声块会被放到 ignored，不应该继续显示成有效边线。

左右边线外侧的黑线也不应成为 active 边线。如果画面中同时有外侧干扰线和内侧真实车道线，算法应选择内侧真实左右边线，外侧线显示为 ignored。

赛道实际宽度约 80cm，但图像里对应多少像素取决于摄像头高度和角度，代码不能只凭 80cm 自动算准。因此现在补线按“左右黑线内侧边缘的像素间距”估计，并在处理图顶部显示 `width=xxx`。

如果自动估计不稳，现场这样调：

```bash
# 先只看画面，观察顶部 width，比如稳定在 360 左右
python3 line_cy.py _dry_run:=true _detect_only:=true _debug_view:=true

# 再固定补线宽度
python3 line_cy.py _dry_run:=true _detect_only:=true _debug_view:=true _lane_width_pixels:=360
```

路口左/右转不够时，优先调这些：

```bash
# 左转更积极
python3 line_cy.py _turn_cmd:=left _dry_run:=false _detect_only:=false _side_follow_speed:=0.10 _left_turn_bias:=0.20 _max_angular:=1.35

# 右转更积极
python3 line_cy.py _turn_cmd:=right _dry_run:=false _detect_only:=false _side_follow_speed:=0.10 _right_turn_bias:=0.20 _max_angular:=1.35
```

## 建议测试流程

```text
1. source ROS 和 robocom_ws 环境。
2. 用 find_camera.py 确认前方巡线摄像头编号。
3. 启动 roslaunch xpkg_bringup bringup_basic_ctrl.launch。
4. 架空轮子或低速空场测试 /cmd_vel 是否正常。
5. 只跑 straight，确认正常双线和路口停车。
6. 测 straight 过路口，确认不会再强制右补线。
7. 测 left，观察紫色补线是否稳定。
8. 测 right，观察紫色补线是否稳定。
9. 最后再慢慢提高 line_speed 或 side_follow_speed。
```

每次只改一个参数，记录现象，不要一口气改很多。
````
