# 循迹斑马线接近与车身对齐设计

日期：2026-07-12

## 目标

小车接近斑马线入口时，不立即停车或直接通过，而是按以下顺序动作：

1. 识别靠近小车一侧的停车横条和横条后方成组的斑马线竖条。
2. 从用于巡线的二值图中屏蔽停车横条和斑马线竖条，防止它们被当成道路边线。
3. 保持真实道路边线巡迹，以较低速度继续向前靠近停车横条。
4. 当停车横条下边缘到达画面高度约 82% 的位置时停车。
5. 根据停车横条的倾斜角原地旋转，直到横条在画面中接近水平。
6. 横条角度连续 5 帧处于允许误差内后，进入原有路口通过流程。

## 根因

当前 `line_cy.py` 有两个直接原因导致实车行为不符合预期：

1. `detect_stopline_before_crosswalk()` 使用 `cv2.minAreaRect()` 检测斜横条，但返回值只保存普通外接框 `(x, y, w, h)`，没有保留横条方向角。
2. `suppress_crosswalk_regions()` 只在 `run_maneuver()` 中使用。正常接近斑马线的 `process_frame()` 仍将原始二值图交给 `line_control()`，所以斑马线竖条会参与边线扫描。

## 状态机

### FOLLOW_LINE

正常双边线或单边线巡迹。

当检测到满足以下条件的斑马线入口候选并连续稳定出现时，进入 `APPROACH_CROSSWALK`：

- 横条位于成组竖条的靠车一侧。
- 至少识别到 3 根横向分布的斑马线竖条。
- 横条位于车辆正前方附近。
- 组合置信度达到现有最低阈值。

### APPROACH_CROSSWALK

每帧先检测斑马线，然后生成专门用于巡线的清理图：

- 屏蔽检测到的停车横条旋转多边形。
- 屏蔽成组斑马线竖条的旋转多边形。
- 每个多边形向外增加少量像素，防止轮廓边缘残留。
- 不屏蔽整个路口矩形，尽量保留真正的左右道路边线。

小车使用清理后的图继续巡线，速度限制为低速接近速度。横条下边缘达到 `align_trigger_y_ratio` 后，进入 `ALIGN_STOPLINE`。

若入口候选短暂丢失，允许使用最近一次可靠结果保持若干帧；持续丢失后进入 `CROSSWALK_WAIT` 并停车等待人工检查，不允许恢复前进。

### ALIGN_STOPLINE

线速度固定为 0，仅发布角速度：

- 横条角度由旋转矩形最长边的两个端点计算。
- 角度归一化到 `[-90, 90]` 度，目标角为 0 度。
- 角速度由角度误差乘比例系数得到，并限制最大值和最小有效值。
- 提供方向符号参数，实车若旋转方向相反可直接取反，无需改算法。

当绝对角度误差不大于 `align_angle_tolerance_deg`，连续达到 `align_stable_frames` 帧后停止旋转，短暂停稳并进入 `MANEUVER`。

如果横条持续丢失或对齐超过时间上限，小车立即停车并进入 `CROSSWALK_WAIT`，不直接盲目通过斑马线。

### MANEUVER

沿用当前路口单边补线逻辑。输入仍使用屏蔽斑马线区域后的二值图，直到斑马线消失并重新稳定检测到双边线，再恢复 `FOLLOW_LINE`。

## 检测结果

`detect_stopline_before_crosswalk()` 在现有字段基础上增加：

- `candidate`：入口组合成立，但未必已经靠近到触发位置。
- `stop_polygon`：停车横条旋转矩形的四个顶点。
- `stop_angle_deg`：停车横条相对画面水平线的角度。
- `stop_bottom_y`：旋转矩形最下方的像素坐标。
- `stripe_polygons`：成组斑马线竖条的旋转矩形顶点。

原有 `stop_box`、`stripe_boxes`、`confidence` 等字段继续保留，避免破坏调试显示和现有流程。

## 可调参数

建议默认值：

- `approach_crosswalk_speed = 0.06`：接近横条速度。
- `align_trigger_y_ratio = 0.82`：横条下边缘进入画面底部区域的阈值。
- `align_kp = 0.025`：每度角度误差对应的角速度比例。
- `align_max_angular = 0.35`：摆正最大角速度。
- `align_min_angular = 0.08`：需要转动时的最小角速度。
- `align_angle_tolerance_deg = 3.0`：认为横条已水平的角度误差。
- `align_stable_frames = 5`：水平状态稳定帧数。
- `align_timeout = 5.0`：对齐动作最长时间。
- `align_angular_sign = 1.0`：实车旋转方向修正，方向相反时改为 `-1.0`。
- `crosswalk_lost_frames = 6`：入口候选允许短暂丢失的帧数。

这些参数通过 ROS 私有参数读取，现场可使用 `_参数名:=值` 调整，不需要重复修改源码。

## 调试显示

处理窗口增加：

- 状态：`FOLLOW_LINE`、`APPROACH_CROSSWALK`、`ALIGN_STOPLINE`、`MANEUVER`。
- 横条角度 `stop_angle`。
- 横条底部比例 `stop_bottom`。
- 对齐稳定帧数。
- 停车横条旋转轮廓和实际屏蔽区域。

斑马线条纹即使仍显示黄色检测框，也不能再出现在巡线扫描的蓝色/青色边线结果中。

## 验证

先使用离线合成二值图或保存的现场帧验证：

1. 斜横条角度的正负和大小计算正确。
2. 横条未到底部时进入低速接近，而不是立即进入路口。
3. 清理图中斑马线竖条被清除，真实道路边线仍保留。
4. 横条倾斜时产生正确方向的角速度。
5. 横条水平连续 5 帧后才进入 `MANEUVER`。
6. 横条丢失或对齐超时后保持停车，不盲目通过。

WSL 只能进行语法、算法和离线图像验证。最终角速度方向、触发位置和速度必须将文件同步到 `/home/eaibot/robocom_ws/src/line_cy.py` 后，在实车低速模式验证。
